# 03 - Structural-to-template registration

Stage 3 of 6 in the pipeline. Registers the RAS-converted structural stack (output of
stage 02, `02_functional_to_structural_registration`) to a population-average reference
template that carries hand-drawn brain-region annotations (defined in stage 04,
`04_annotation`). Registration is landmark-based affine followed by SyN deformable
registration. The resulting forward/inverse transform chain is what stage 05
(`05_roi_pullback`) uses to pull template region labels back onto native
functional/structural space.

The original project evaluated several parameter variants of the deformable-registration
step. Only the accepted, final variant is included here; nothing in this codebase or
data should be read as leaving other variants out by omission or oversight.

## Run order

```
fix_template_geometry.py           # builds the fixed-image template with a trusted affine
register_structural_to_template.py # landmark affine + SyN registration
qc_overlay.py                      # visual QC overlays (FIJI/ImageJ)
```

## Environment

`antspy` environment: `ants`, `nibabel`, `numpy`, `scipy`, `scikit-image`, `tifffile`.

## Inputs / outputs

All paths below are relative to `DATA_ROOT/03_structural_to_template_registration/`
(`DATA_ROOT` defaults to `data_for_upload/` next to `code/`; override with the
`PIPELINE_DATA_ROOT` environment variable).

- `landmarks.csv` -- 19 manually-placed landmark pairs (moving = structural stack, fixed
  = template), by voxel index in each volume.
- `stage0_geometry_fixed/template_ras.nii.gz` -- the fixed/reference template volume,
  with a trusted, byte-identical NIfTI affine (see `fix_template_geometry.py`).
- `stage0_geometry_fixed/02F_stack_ras_cropped.nii.gz` -- the moving structural stack,
  RAS-converted and cropped.
- `stage0_geometry_fixed/mask_ras_cropped.nii.gz` -- brain mask for the structural stack,
  same grid as above.
- `stage1_registration/landmark_affine.mat` -- the 12-DOF affine fit directly from the
  landmark pairs.
- `stage1_registration/fwd_0GenericAffine.mat`, `fwd_1Warp.nii.gz`,
  `fwd_1InverseWarp.nii.gz` -- the final forward-transform chain (affine + SyN warp) and
  its inverse warp, as produced by `ants.registration`.
- `stage1_registration/qc/*.tif` -- QC overlay stacks (see below), produced by
  `qc_overlay.py`.

## Provenance note: `02F_stack_ras_cropped.nii.gz` and `mask_ras_cropped.nii.gz`

These two files are the RAS-converted, cropped structural stack and its mask. The script
that produced them from the raw structural stack (`fix_geometry.py`) has been lost and
could not be recovered from the original project; only its output survives, which is why
these two NIfTI files are provided directly as starting inputs for this stage rather than
generated by a script in this release.

Based on documentation found in a sibling script's docstring, that lost step converted
the raw structural stack into a NIfTI volume with array axis order (X, Y, Z), identity
direction cosines, origin (0, 0, 0), and `xyzt_units="micron"` -- i.e. the pixdim values
in the header are literal micron spacings. This is a deliberately different convention
from the standards-compliant millimeter convention used by the ITK-SNAP-authored
annotation volumes from stage 04. Anyone re-deriving this conversion from raw data should
match that convention (micron pixdim, identity direction, zero origin) for the outputs to
register correctly against `template_ras.nii.gz`.

## Known caveat: the Rigid refinement stage is a silent no-op

`register_structural_to_template.py` requests a Rigid-only refinement
(`ants.registration(type_of_transform="Rigid", ...)`) between the landmark affine fit and
the SyN deformable stage. This has been confirmed to silently fail to converge for this
data: the landmark-fit affine carries real scale (roughly 1.11-1.15 on the diagonal),
which breaks the near-identity assumption that ANTs' Rigid-family optimizers rely on for
their first gradient step. Every Rigid-family preset tested (Rigid, QuickRigid,
DenseRigid, BOLDRigid) throws an internal ITK exception within 1-2 gradient iterations
given this initialization. `ants.registration()` catches that exception internally and
silently returns the unmodified input transform, with no error surfaced to the caller.

Net effect: the accepted registration is, in practice, landmark-affine + SyN, not
landmark + Rigid + SyN, despite what the script requests. This is a known, confirmed
characteristic of the accepted result -- not a bug introduced during cleanup for this
release -- and is stated here and in the script's docstring so it is not mistaken for a
genuine rigid-refinement step when interpreting the fitted transform chain.

## QC outputs

`qc_overlay.py` writes two 2-channel TIFF stacks to `stage1_registration/qc/`:

- `check_template_vs_warped_2ch_stack.tif` -- template + structural warped into template
  space (forward chain), on the template's grid.
- `check_structural_vs_warped_template_2ch_stack.tif` -- structural stack in its own
  native space + template warped into structural space (inverse chain), on the
  structural stack's grid. This is the view relevant to stage 05's ROI pull-back, which
  uses the same inverse chain.

## Known limitation

A local structural-vs-template misalignment remains at the dorsal/top-middle brain
boundary, worst at the deepest included plane and tapering off at shallower depth. This
was an accepted limitation in the original project, not fixed in the shipped
registration.
